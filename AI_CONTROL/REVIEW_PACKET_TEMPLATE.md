# Strategic Review Packet Template

Use this when asking an external GPT reviewer to reason about InsPoly without access to the full repository or Codex thread.

## Required Packet Sections
1. Project purpose in 5-8 sentences.
2. Current architecture summary.
3. Current state and gate decisions.
4. What changed in the latest cycle.
5. Why those changes were made.
6. Files changed, grouped by function.
7. Tests/validation run and results.
8. Known unresolved issues.
9. Strategic risks and likely tunnel-vision risks.
10. Next 1-3 possible strategic directions, with pros/cons.
11. Questions requiring operator decision.
12. Exact guardrail excerpts constraining next steps.

## Prompt To External GPT
```text
You are the strategic architecture reviewer for this coding project.
I am giving you a self-contained review packet generated by Codex. You do not have access to the full repository unless I paste additional files.

Your task:
1. Identify whether Codex is overfitting to local bugs instead of strategic architecture.
2. Check whether the proposed next steps align with the project purpose and guardrails.
3. Identify hidden risks, missing validation, architectural drift, and unnecessary complexity.
4. Recommend the next 1-3 highest-leverage tasks for Codex.
5. Write a precise prompt I can paste back into Codex.
6. Separate safe implementation tasks from tasks that require explicit operator approval.

Here is the packet:
[PASTE AI_CONTROL/STRATEGIC_REVIEW_PACKET.md]
```

## Prompt Back To Codex
```text
Before implementing anything, read AGENTS.md, PROJECT_MEMORY.md, AI_CONTROL/PROJECT_MEMORY.md, AI_CONTROL/STRATEGIC_MAP.md, AI_CONTROL/CURRENT_STATE.md, AI_CONTROL/INVARIANTS_AND_GUARDRAILS.md, AI_CONTROL/DECISION_LOG.md, AI_CONTROL/STRATEGIC_BACKLOG.md, AI_CONTROL/LAST_STRATEGIC_REVIEW.md, and the relevant source/test/docs files.

Use the external GPT recommendations as advisory input only. Reconcile them against current code, root memory, and repository guardrails.

Required output before code changes:
1. Current understanding of the project state.
2. Strategic objective of the task.
3. Modules/files likely affected.
4. Invariants that must not be touched.
5. Smallest safe implementation path.
6. Risks of local overfitting or tunnel vision.
7. Tests/validation commands to run.
8. Whether operator approval is required before implementation.

Do not edit code until this plan is written.
```
